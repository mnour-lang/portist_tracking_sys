# Portist Lojistik — نظام الفواتير والشحنات

تطبيق عربي (RTL) من ملف HTML واحد (`portist_invoice.html`) + خادم Vercel (`api/index.js` ← `lib/core.js`) فوق Neon Postgres.

## النشر
- الدفع إلى GitHub يُنشر تلقائياً على Vercel. الواجهة المنشورة هي `public/index.html` (نسخة من `portist_invoice.html`).
- بعد أي تعديل: `cp portist_invoice.html public/index.html`

## متغيرات البيئة (Vercel → Settings → Environment Variables)
| المتغير | الغرض |
|---|---|
| `DATABASE_URL` (أو متغيرات Neon) | الاتصال بقاعدة البيانات |
| `APP_PASSWORD` | مفتاح الربط/الإعداد الأول |
| `PEPPER` | ملح تجزئة كلمات السر على الخادم. **يجب أن يساوي القيمة المخزنة حالياً** في الجدول `props` (المفتاح `PEPPER`)؛ تغييره يُبطل كل كلمات السر. |
| `SESSION_SECRET` | (اختياري) مفتاح توقيع رموز الجلسة؛ إن غاب يُشتق من `PEPPER`. |
| `ALLOW_LEGACY_AUTH=1` | (طارئ فقط) يسمح بالمصادقة القديمة بمجزّأ كلمة السر. الافتراضي: مغلق. |

## الأمان
- بعد الدخول يستلم المتصفح رمز جلسة موقّعاً (30 يوماً) يبطل عند تغيير كلمة السر أو إيقاف الحساب؛ لا يُرسل مجزّأ كلمة السر مع كل طلب.
- كتابة/قراءة البيانات المشتركة (`kvput/kvget`) مقيّدة بصلاحيات كل مفتاح؛ سجل النشاط للمدير فقط.

## المراقبة والنسخ
- الإعدادات ← «سجل أخطاء النظام»: أخطاء الخادم والمتصفح (آخر 300).
- الإعدادات ← «النسخ التلقائي للخادم»: نسخة يومية تلقائية (آخر 14) + نسخ يدوية + استعادة (للمدير). لا تشمل الصور وملفات التصدير وحسابات المستخدمين — استخدم «النسخة الاحتياطية» العادية للنسخة الكاملة.

## الاختبارات
`bash tests/run_all.sh` ← يجب أن تنتهي بـ `ALL OK` (تحتاج node و python3 + playwright).

## تغييرات البنية (الترحيلات)
- لا تُعدَّل جداول القاعدة يدوياً. أي تغيير يُضاف كعنصر جديد في `MIGRATIONS` داخل `lib/core.js` (معرّف مرتب مثل `002_...`)، ويُنفَّذ تلقائياً مرة واحدة عند أول طلب بعد النشر، ويُسجَّل في الجدول `schema_migrations`.
- قبل أول ترحيل جديد يأخذ الخادم نسخة أمان (نوعها `pre-migrate`) تجدها في الإعدادات ← النسخ التلقائي.
- أعمدة المبالغ (`total`, `paid`) في الفواتير والوصولات من نوع `numeric(18,4)` لتفادي أخطاء الفاصلة العائمة.

## هيكل الكود (مهم)
الواجهة تُكتب في مجلد `src/` وتُبنى إلى ملف واحد:
- `src/html/` الرأس والجسم (HTML) والذيل، `src/css/` الأنماط، `src/js/` الكود مقسّماً حسب الميزة (i18n، أدوات، مزامنة، دفعات، شحنات، مستندات، تكاليف، نسخ احتياطي، مستخدمون، تنقل، لوحة المعلومات، مركز التكاليف، ستوك التصديرات).
- **لا تعدّل `portist_invoice.html` ولا `public/index.html` مباشرة**؛ عدّل ملفات `src/` ثم شغّل `node tools/build.js` (أو `npm run build`). يفحص البناء الصياغة ويكتب الملفين.
- `node tools/build.js --check` (يُشغَّل أول `tests/run_all.sh`) يفشل إن كان الملف المبني لا يطابق المصادر.
- ملفات `src/js/*` تُدمج بالترتيب الأبجدي في سكربت واحد، فالتصريحات العامة مشتركة بينها كما كانت.
